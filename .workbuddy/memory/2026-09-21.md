## 交付后修订 v2：sc08 回撤数值不可读（用户报告）

**用户报告**：1:28（88.0s，sc08 最大回撤）里红利低波50 / 沪深300 / 中证500 的百分比是白字，与背景重叠看不清。

**根因**（典型"声明与实际不符"）：宽柱分支写成 `color: labelInside ? C.invertText : f.color`，
意图是"柱子够长就把数字放进柱内用近白字"，但同一元素还用了固定 `width: 180` + `textAlign: "right"`。
右对齐文字的右边缘落在 `left + width` = **柱端之外 168px**，于是近白字被画在浅色底板上。
**柱子越长越触发该分支** —— 所以恰好是 −16.53% / −38.45% / −39.48% 三行中招，柱最短的 −12.91% 走另一分支反而正常。

**量化**：修前标签区实测对比度 **1.06:1**（沪深300）/ 1.09:1（中证500）；修后约 **14:1**。

**修法**：去掉内外分支，标签一律锚在柱端外侧 16px、左对齐、统一墨色 `C.ink`；
横轴满刻度 MAX 0.40→0.46 给最长柱留标签净空（四柱同比缩放，比例与零基线关系不变）；
标签不透明度接到柱子生长进度（0.4+0.6·p）。
**没有用身份色染数字**：中证500 的 #C4791F 对底板只有 3.1:1，会变成新的短板；
身份已由色块+名称+代码三重承担。

### 新增回归自检 `projects/etf-100k-four-fund-race/check_composition.py`

两条硬性检查，都用还原旧写法的夹具验证过会失败（不是空转）：
1. **静态不变量**：浅色墨 `C.invertText` 只能出现在显式 `background: C.invert` 的容器里，且禁止由数据条件选色。
   坑：判断"有没有深色底片"**不能**写 `"C.invert" in window` —— 它是 `C.invertText` 的子串，永远为真，检查会变摆设。
2. **实测安全区**：对成片抽帧求有墨迹的最左/最右列与最低行。
   坑：**不要每帧单独调一次 ffmpeg 并 `select` 到第 n 帧**，那是 O(n²) 解码，2970 帧抽 99 帧会慢到被杀（exit 137）。
   正确做法是一次 `ffmpeg -vf "select='not(mod(n\,30))'" -vsync 0 -frame_pts 1` 全部抽出。实测 2.2s。

### 通用教训（已写进 skill）

- **文字颜色不能由数据条件决定**。数据的值一变，底色就变，可读性就无法在源码层面保证。
- **`textAlign: "right"` + 固定 `width` 是一个陷阱**：文字右边缘落在 `left + width`，不是 `left`。
  想"右对齐到某个 x"要写 `left: x - width`，或者直接把容器左边贴到 x 用 `left` 对齐。
- **"浅色字放在彩色柱内"这个模式要慎用**：柱色是身份色，亮度不可控；
  中证500 的橙色上身白字只有 3.1:1。身份色只适合做小面积标识，不适合做大字底色。
